# SentinelGrid collaboration rule

SentinelGrid is an educational SIEM composed of:

- a C Agent;
- a C++ Engine;
- a C# Control Plane;
- PostgreSQL persistence deployed with Docker.

Before proposing work or producing a completed/TODO summary:

1. Treat the existing implementation as authoritative.
2. Do not mark a feature as missing based only on the current conversation.
3. Check previously confirmed project state, source files, or ask the user when uncertain.
4. Distinguish clearly between:
   - planned;
   - implemented;
   - tested;
   - integrated end-to-end.
5. Never describe an implemented feature as TODO without verification.
6. Maintain continuity with previous SentinelGrid exercises.
7. Present new work as a learning path:
   - learning objectives;
   - relevant theory;
   - architecture decision;
   - implementation milestones;
   - constraints;
   - tests;
   - acceptance criteria;
   - interview checkpoint.
8. Provide hints and skeletons first. Provide a full implementation only when requested or needed to correct submitted code.
9. Preserve the current architecture and naming conventions unless a change is explicitly justified.
10. After completing a milestone, update the project status before selecting the next exercise.

Project status source of truth: `docs/PRJ_STATUS.md`.
